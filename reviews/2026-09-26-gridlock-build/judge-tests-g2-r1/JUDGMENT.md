## Findings

### G2-TEST-01 — P2 / important: late overlap response test waits a fixed 100 ms

**Location:** `tests/e2e/test_overlap_detail.py:194`, especially `:223`; relevant production guards are `web/js/overlap-detail.js` inside `open()` before and after `response.json()`.

**Trigger and gap:** the test holds the old fetch, opens a new pair, releases the old fetch, sleeps 100 ms, and then checks that its JSON was not consumed and DRESDEN remains. A delayed event loop can satisfy those assertions before the old continuation is processed. The held response also contains only an incomplete overlap object. It exercises the pre-JSON guard but does not independently exercise a response whose headers arrived while current and whose JSON resolves after a new selection. This falls short of the task's late-response acceptance and checklist J's condition-based waits.

**Exact proposed repair:** retain `test_delayed_old_detail_cannot_replace_new_selection` and parameterize delayed headers / delayed JSON, using a complete old payload obtained before interception. Add a controlled completion barrier for the released fetch/JSON promise and observe the subsequent browser task after the continuation has run. Await that barrier with `wait_for_function` or an awaited page promise; remove the fixed wait without removing assertions. In both variants assert the new pair's exact heading/name, hash, pressed row, and highlighted project IDs after release. In the header-delay variant also retain the no-JSON-consumption assertion.

**Acceptance:** prove RED against a scratch mutation that removes the relevant stale-request guard in each phase; prove GREEN with both guards, repeat the focused race cases three times, then run the owning lane gate. No fixed sleep and no weaker assertion. This is a test-quality defect; I did not reproduce a production failure.
