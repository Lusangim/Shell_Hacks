## Browser-key exposure boundary / security review

When explicitly enabled with a configured browser key, `/api/map-config` deliberately returns that key to the local page. It is visible to the browser and local clients, so it is not an authentication secret protecting this application. Configure API/referrer restrictions in the key provider before founder-run online use. Settings/model repr hide the key; no logging or error text includes it. HTTP responses use no-store, no CORS, JSON with nosniff, same-origin resource policy, the existing localhost/127.0.0.1 Host restriction and explicit foreign Origin/Fetch-Metadata rejection. These browser controls do not authenticate local processes or protect against code already executing on the application's own origin.

The default is Google off, with exact `default-src 'self'` and no key-file read/stat. The enabled CSP lists explicit official Maps script/connection/image hosts and Google font hosts; inline styles are enabled only in this mode for Maps UI styling. No wildcard Google domains or broad https source are added. The API makes no outbound request. The Google host allowlist has not been live-validated; this lane's base contains no GoogleMutant source. A real Maps/Satellite request was neither authorized nor performed.

Enabled/key-present HTML and config responses use `Referrer-Policy: strict-origin-when-cross-origin` so a Maps request can send the local origin for provider-side referrer restrictions. Other responses and all off/no-key cases retain `no-referrer`. Only origin is exposed on HTTPS cross-origin requests; page query/fragment state is not sent as the referrer.

## For WEB

Fetch `/api/map-config` from the same origin. Shape: `{google_enabled: boolean, google_key: string | null, offline_available: boolean}`. Use `/basemap/gasc.pmtiles` as the local PMTiles URL. Missing archives return fixed typed 404 and availability false, allowing the existing offline fallback. Show/load Google only with enabled/key present, online state and explicit user choice; keep offline usable on load failure. Never write the browser key to console, persistent storage, URL state or artifacts.
