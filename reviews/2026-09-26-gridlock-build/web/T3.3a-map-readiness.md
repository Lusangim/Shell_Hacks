Classification: WEB test readiness race, exposed reproducibly on this held API branch. The tests' independent API requests finish before the page finishes its own asynchronous shell load. `web/js/api.js` loads four shell resources through `Promise.all`; `web/js/app.js` renders the map after that load; `web/js/map.js` adds the project test IDs when Leaflet adds the layers. The original immediate evaluation can therefore run before any project paths exist. This is not evidence that the map features are unreachable after rendering.

A read-only browser probe used the fixture's isolated server and the same eligibility/hit-test predicate for both journeys. At the original selection point, both pages reported:

```json
{"features": 0, "reachable": 0, "project": null, "status": "Loading public plans."}
```

After waiting on the predicate, both reported:

```json
{"features": 181, "reachable": 23, "project": "desc-p33", "status": "489 ranked opportunities loaded."}
```

In both probe journeys a real pointer click opened project detail, selected the exact expected pair `desc-p33__sertp-p150-ef263c`, and the separate highlighted-pair button opened overlap detail with two selected map features. Both recorded zero page errors. The probe closed its pages, browser, and fixture server in `finally` blocks.
