## Review correction: duplicate search labels — 2026-09-26

The real `Bluffton` response has two `Bluffton town` places at different source coordinates. The real `WANSLEY 500 KV` response has two projects with the same displayed name and different source refs. Previously both pairs produced identical datalist values, and the persistent label lookup could select a result from an older query.

Changed `web/js/search.js` and `tests/e2e/test_search.py`. Within each current result set, duplicate labels now receive a datalist value with their source ref or source coordinates. The selected visible label remains exactly the API label through `textContent`. The choice lookup clears at the start of each new query and for short queries; selecting a current datalist value keeps the current results long enough for Enter to center the chosen record. Fetch stays relative to `/api/search`, and the late-response request token remains in place.
